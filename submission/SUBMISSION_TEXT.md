【作品名称】
今天吃这桌

【作品形态与创作动机】
「今天吃这桌」是一款面向支付宝「生活好帮手」赛道的轻量化餐饮聚餐决策智能体（响应式 Web 应用 + 标准化 Agent Skill 契约），开箱即用、无需配置任何密钥。

创作动机源自每个人都会遇到、却始终没有顺手工具解决的高频麻烦：晚上约三五好友吃饭，或者临时负责安排部门 8 人聚餐，选店要翻地图看距离、翻榜单看评分、还要反复确认预算超没超；好不容易定下 3 家候选饭馆，坐下来点菜又发愁——4 个人该点几个硬菜几个素菜才不浪费？有人不吃辣或控糖怎么避开？支付宝口碑里看到团购套餐，到底买团购再加两道菜划算，还是直接买代金券单点划算？这顿饭算下来人均到底多少钱？

「今天吃这桌」把「选 3 家真馆子 → 按人数配好一桌菜 → 查团购算差价 → 定店通知与支付宝群收款 AA」串成一次 30 秒完成的丝滑决策闭环。

【团队/个人介绍】
独立开发者 BreakNeo（GitHub: @breakneo），长期专注 AI Agent 工具链与贴近真实日常消费场景的轻量应用研发，坚持「真数据、零废话、打开就能用」的产品原则，致力于用大模型与本地服务接口结合，减少普通人在日常消费决策中的重复比对成本。

【目标用户与核心痛点】
目标用户：城市上班族、朋友聚会组织者、部门团建/商务聚餐负责点菜与控预算的「攒局人」。
四大核心痛点：
1. 多维约束筛选难：地图和榜单只能按单一维度排序，无法同时兼顾「地点距离 + 口碑评分 + 总预算或人均上限 + 朋友/单位场景 + 口味忌口」。
2. 按人数点菜易踩坑：点少了吃不饱显得小气，点多了铺张浪费且超预算，还容易漏掉同桌人的忌口。
3. 团购真假划算算不清：面对套餐和代金券，普通用户很难快速心算出「套餐份量够不够 N 个人吃、叠加补菜后比纯单点到底省多少」。
4. 聚餐前后收尾琐碎：定店后要手动整理地址和导航发群里，吃完饭还要按是否喝酒手动分账。

【核心功能与使用说明】
打开链接 https://breakneo.github.io/earn-alipay-dining/ 即可直接体验（手机与电脑端均已适配）：
1. 一键输入聚餐约束：输入全国任意商圈、写字楼或地铁站（也可点击顶部杭州黄龙、北京国贸、上海陆家嘴、成都太古里一键试玩），设置用餐人数、按人均或按总预算控制金额、选择聚餐场景（朋友小聚/单位聚餐/商务宴请/家庭聚餐）并勾选忌口标签。
2. 真实 3 家饭馆横评与「换一家」：实时拉取目标地点周边 2 公里内高德真实营业餐厅，自动剔除奶茶/小吃档口与严重超预算店铺，兼顾菜系多样性选出 3 家候选，呈现横向对比表；不满意任意一家可一键从真实候补池「换一家」并重新配菜。
3. 按人数防浪费配菜与预算精算：针对每家候选餐厅，按科学配比（例如 4 人推荐 1 凉菜 + 2 硬菜 + 1 时蔬 + 1 汤/主食，8 人单位聚餐自动扩容）生成避开忌口的具体点菜清单，算出本桌参考总价、折合人均与预算结余状态。
4. 阿宝查团购联动与真实团购比价器：每张餐厅卡片均提供「高德地图直达」与「一键复制问阿宝查实时团购」按钮；点开「粘贴团购算差价」，将支付宝、口碑或点评里看到的真实团购套餐/代金券文案粘贴进去，AI 立即评估份量是否够吃、有无忌口冲突，并算出「团购加菜 vs 纯单点」的准确省钱金额。
5. 定店通知、日历提醒与支付宝群收款 AA：点击「就定这家」，一键复制含地址与导航链接的群约饭通知、导出标准 .ics 手机日历提醒，并支持输入饭后实付总额及酒水费用（区分喝酒与不喝酒人均），一键复制支付宝群收款 AA 账单。

【所使用的主要模型、工具、第三方服务与数据来源】
1. 地图与真实餐厅数据源：高德开放平台 Web 服务 API（POI 文本检索、地理编码、周边餐饮搜索，实时获取全国真实餐厅名称、地址、距离、高德评分、人均消费与营业时间）。
2. 大语言模型：通过国家超算互联网（SCNet）OpenAI 兼容接口调用 GLM-5.3-Flash，用于多约束点菜搭配、团购策略生成与团购套餐比价推理。
3. 云端安全代理与托管：Cloudflare Workers 提供 /poi 与 /chat 双路由限流代理，所有第三方 API 密钥均加密存储在 Cloudflare Secrets 中，前端源码与静态页面零密钥暴露；静态页面托管于 GitHub Pages。
4. 合规与真实性保障：全部推荐餐厅均为高德实时检索的真实商户，绝不虚构不存在的门店或编造未核实的实时团购标价；推荐菜品单价明确标注为基于该店真实人均的参考估算，实际以门店当日菜单与支付宝/阿宝实时团购页为准。
