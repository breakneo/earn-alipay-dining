【作品名称】
今天吃这桌

【作品形态与创作动机】
「今天吃这桌」是一款面向支付宝「生活好帮手」赛道的轻量化餐饮聚餐决策智能体（手机与电脑自适应 Web 应用 + 标准化 Agent Skill 契约），开箱即用、无需配置任何密钥。

创作动机源自每个人都会遇到、却始终没有顺手工具解决的高频麻烦：晚上约三五好友吃饭，或者临时负责安排部门 8 人聚餐，选店要翻地图看距离、翻榜单看口碑、还要反复确认预算超没超；好不容易定下几家候选饭馆，坐下来点菜又发愁——4 个人该点几个硬菜几个素菜才不浪费？有人不吃辣或控糖怎么避开？在支付宝口碑和高德看到团购套餐，到底买团购再加两道菜划算，还是买代金券单点划算？这顿饭算下来人均到底多少钱？

「今天吃这桌」把「按距离与家数挑好饭馆 → 按人数配好一桌菜 → 支付宝口碑/高德团购比价 → 一键发群约饭通知与高德导航」串成一次 30 秒完成的丝滑决策闭环。

【团队/个人介绍】
独立开发者 BreakNeo（GitHub: @breakneo），长期专注 AI Agent 工具链与贴近真实日常消费场景的轻量应用研发，坚持「真数据、零废话、打开就能用」的产品原则，致力于用大模型与支付宝、高德本地生活生态结合，减少普通人在聚餐决策中的重复比对成本。

【目标用户与核心痛点】
目标用户：城市上班族、朋友聚会组织者、部门团建与商务聚餐负责选店点菜的「攒局人」。
四大核心痛点：
1. 多维约束筛选难：地图和榜单只能按单一维度排序，无法同时兼顾「选定地点距离范围 + 筛选家数 + 口碑评分 + 总预算或人均上限 + 聚餐场景 + 口味忌口」。
2. 按人数点菜易踩坑：点少了吃不饱显得小气，点多了铺张浪费且超预算，还容易漏掉同桌人的忌口。
3. 团购真假划算算不清：面对套餐和代金券，普通用户很难快速心算出「套餐份量够不够 N 个人吃、叠加补菜后比纯单点到底省多少」。
4. 聚餐定店发群琐碎：拍板后还要手动整理时间、餐厅、地址与高德导航链接发到群里。

【核心功能与使用说明】
打开链接即可在手机或电脑端直接体验（全面适配移动端竖屏，无横向滚动条）：
1. 灵活输入聚餐约束：支持顶部「快捷试玩」下拉一键填入常见城市聚餐场景，或自由输入全国任意商圈、写字楼、地铁站，自由选择搜索范围（500米内至5公里内）、筛选餐厅家数（默认 3 家，支持 1 至 10 家）、用餐人数、按人均或按总预算、聚餐场景与口味忌口标签。
2. 候选饭馆横评与「换一家」：实时拉取指定范围内高德营业餐厅，自动剔除奶茶/茶馆等非正餐档口与严重超预算店铺，呈现自适应对比清单；不满意任意一家可一键从周边候补池「换一家」并重新配菜。
3. 按人数防浪费配菜与预算精算：针对每家候选餐厅，按人数科学配比（例如 4 人推荐 1 凉菜 + 2 硬菜 + 1 时蔬 + 1 汤/主食，8 人单位聚餐自动扩容）生成避开忌口的具体点菜清单，算出本桌参考总价、折合人均与预算结余状态。
4. 支付宝/口碑/高德团购联动与比价器：每张餐厅卡片均提供「高德地图直达」与「复制问阿宝查团购」按钮；点开「粘贴支付宝/口碑团购文案，帮我算差价」，贴入看到的团购套餐或代金券文案，立即评估份量、忌口冲突以及「团购加菜 vs 纯单点」的准确省钱金额。
5. 一键生成简洁约饭通知：点击「就定这家 · 生成约饭通知」，输出干净得体的群通知（含时间、餐厅、地址与高德导航链接，隐去花销与菜单避免社交尴尬），支持导出标准 .ics 手机日历提醒，底部亦折叠收纳可选的饭后 AA 分摊计算工具。

【所使用的主要模型、工具、第三方服务与数据来源】
1. 地图与真实餐厅数据源：高德开放平台 Web 服务 API（POI 文本检索、地理编码、周边餐饮搜索，实时获取全国真实餐厅名称、地址、距离、口碑评分、参考人均与营业时间）。
2. 大语言模型：通过国家超算互联网（SCNet）OpenAI 兼容接口调用 GLM-5.3-Flash，用于多约束点菜搭配、团购策略生成与团购套餐比价推理。
3. 云端安全代理与国内可直连托管：全部第三方 API 密钥均加密存储在服务端环境变量中，前端源码零密钥暴露；提供国内网络可稳定直连的部署入口与完整开源代码仓库。
4. 合规与真实性保障：全部推荐餐厅均为高德实时检索的真实商户，绝不虚构不存在的门店或编造未核实的实时团购标价；推荐菜品单价明确标注为基于该店参考人均的估算，实际以门店当日菜单与支付宝/口碑实时团购页为准。
